# Project review TODO

Review of the Go implementation and repository tests. Priorities reflect impact, not implementation order: P0 = potential data loss, P1 = broken behavior, P2 = robustness or compatibility, P3 = API/product ideas. Findings distinguish locally demonstrated behavior from code-inspected issues and proposals. Completed fixes are checked below.

## Confirmed findings

- [x] **P0 — Protect source directories before deleting output.** Added canonical path validation in `Site.New`, at the beginning of every build mode, and immediately before disk cleanup. Reject output equal to/above the site or overlapping config, content, templates, static, themes, data, repository metadata or configured watch paths; resolve symlinks and missing parent suffixes. Regression tests cover source/ancestor paths and symlinks changed after construction, and verify source sentinel files survive rejected builds.
- [ ] **P1 — Return template rendering failures.** `internal/site/site.go:renderAllPages` replaces any template error with bare HTML containing the Markdown body and reports success. Undefined functions, failed data fetches and missing selected templates silently publish broken pages. Propagate the error with source/template context and fail the build; inspect other renderers for the same pattern.
- [ ] **P1 — Reload templates and configuration in serve mode.** `Site.New` loads config/templates once; `Site.Load` only reconstructs content. The watcher therefore rebuilds against stale configuration and template sources. Reload into a fresh candidate site and publish it only after a successful build; preserve the last successful output on failure.
- [ ] **P1 — Watch nested directories without watching build output.** `internal/server/serve.go:Run` adds only the top-level content/templates/static directories to fsnotify; existing nested directories and newly created directories are not registered. Editing `content/blog/post.md` can therefore fail to rebuild. Every event in the config's parent directory is treated as a rebuild trigger, including unrelated root-level output/cache changes. Register source directories recursively (including theme sources), add new directories, filter relevant events, resolve extra paths against the site root, and surface watcher registration errors.
- [ ] **P1 — Propagate scaffold write errors.** `cmd/kopkop/main.go:runInit` discards every write error after `zola.toml`. Existing templates without `--force`, permission failures, or invalid target directories can produce a partial scaffold reported as successful. Preflight conflicts and return all write failures. Also support or document flags after the directory argument: Go's flag parser stops at the first positional argument.
- [ ] **P1 — Make link-check caching expire.** `internal/linkcheck/checker.go:CheckExternalLinks` never retries any URL already in the cache, including transient failures. Successful cached links can remain "OK" forever after disappearing. Add timestamps/TTL and a refresh option; make results deterministic and surface cache write errors.
- [ ] **P2 — Parse anchor targets as HTML.** `internal/linkcheck/checker.go:checkURL` searches only for the exact string `id="fragment"`. Valid single-quoted/unquoted attributes, legacy named anchors, and percent-encoded fragments are mishandled; text inside scripts can cause false positives. Parse HTML attributes and decode URL fragments; bound response sizes and test these cases.
- [ ] **P2 — Cleanly stop the development server and WebSockets.** `internal/server/serve.go:Run` returns `http.ErrServerClosed` on ordinary shutdown, while `main` ignores only `context.Canceled`, so Ctrl-C can report failure. Workers can outlive Run when ListenAndServe fails; closed watcher channels are not checked; WebSocket writes hold the hub lock without deadlines and errors are ignored. Use a derived cancellation context, bounded shutdown, connection cleanup and write deadlines.
- [ ] **P1 — Make image output names unique.** `internal/imageproc/processor.go:Resize` uses only basename and dimensions for `processed_images/<name>-<width>x<height>.<ext>`. Two different `content/a/photo.png` and `content/b/photo.png` inputs overwrite each other (potentially concurrently), and both templates receive the same URL. Include a digest of input bytes and transformation settings; cache repeated transforms and test same-basename inputs.
- [ ] **P2 — Honor the selected output filesystem consistently.** `Site.Build` calls `search.BuildIndex` and `copyStatic` through disk paths; template image helpers also retain the disk OutputFS supplied in `Site.New`. Memory builds still write these artifacts to disk. Route every artifact through one build output interface; verify disk/memory/both produce equivalent manifests without unintended disk writes.
- [ ] **P0 — Enforce filesystem containment for reads and writes.** `internal/filesystem/filesystem.go:DiskFS.full` joins unchecked names, permitting `../` escapes. `load_data`, hashes and image helpers reach it; `search.BuildIndex` also writes unchecked `search.index_path` directly. Colocated asset copying bypasses `writeOutput` path validation. Validate normalized relative paths at the filesystem boundary and reject symlink escapes; test traversal in aliases, explicit page paths, feed filenames and search paths. Prefer `os.Root` where appropriate.
- [ ] **P1 — Detect output collisions before rendering.** Two pages with the same slug/path are silently merged in `renderAllPages`' artifact map; parallel completion decides the winner. Sections, aliases, taxonomy slugs, static files and colocated assets can then overwrite generated files. Build an output manifest with source ownership, fail on ambiguous collisions, and explicitly document allowed site-over-theme overrides.
- [ ] **P1 — Apply base URL overrides before constructing the content graph.** The CLI calls `s.Load` before `s.Build(BaseURL: ...)`; Build changes `s.Config.BaseURL` but not the pages/sections or `Library.Permalinks`. Templates and generated URLs can mix production and override hosts. Compute an effective build config before loading or regenerate all derived URLs; test pages, internal links, taxonomy URLs, feeds and sitemaps together.
- [ ] **P1 — Render all content before exposing it to templates.** Pages render before section Markdown, so page templates calling `get_section` see empty section content on an initial build. Sections are processed sequentially, so section templates can see unrendered later sections. Split content rendering from output rendering and make the fully rendered graph available to every template.
- [ ] **P1 — Use the shortcode pipeline for sections and summaries.** Sections call `markdown.RenderContent` directly and do not expand shortcodes; section Markdown errors are discarded. Page HTML shortcodes are substituted only in `rendered.Body`, leaving placeholders in `rendered.Summary`. `markdown.extractSummary` skips heading/link/asset transformations, so links such as `@/post.md` remain unresolved in summaries. Render once and derive summary from that result, with regression cases before/after `<!-- more -->`.
- [ ] **P1 — Respect custom sitemap/feed templates and feed formats.** `renderSitemap` and `renderFeed` bypass the template manager. Every configured feed filename, including `rss.xml`, receives Atom XML via `defaultAtomXML`; taxonomy feeds do the same. Select the configured template and appropriate Atom/RSS fallback. Existing feed tests assert file existence, so add content/schema assertions and template override tests.
- [ ] **P1 — Correct load_url cache identity and format detection.** `internal/templates/manager.go` caches by method, URL and body but omits headers; requests differing in authorization or content negotiation can return another request's response. Cache misses prefer URL extension before Content-Type while hits reverse that precedence, so an identical call can return a different type. Normalize headers into the key, share one format resolution path, and coalesce concurrent identical requests (especially important for POST side effects).
- [ ] **P1 — Publish rebuild output atomically.** `Run` serves `s.MemoryOutput` while `Build` replaces that pointer and populates the new filesystem. MemoryFS locks do not protect the pointer, and requests can see partial output or fall through to stale disk HTML. Disk builds delete the previous output before rendering succeeds. Build into a separate snapshot/staging directory, then swap only after success; exercise simultaneous requests and failed rebuilds under the race detector.
- [ ] **P2 — Make nested transparent sections deterministic.** `internal/content/loader.go:attachPagesToSections` propagates transparent-section pages in map iteration order. With nested transparent sections, visiting an ancestor before a descendant means newly inherited pages never reach the root. Propagate deepest sections first or walk ancestry explicitly; sort taxonomy page lists as well (`buildTaxonomies` also appends in map iteration order).
- [ ] **P2 — Fix heading ID collisions and TOC titles.** `markdown.transformHeadings` counts only the original normalized heading text: `# Foo`, `# Foo`, `# Foo-1` produce duplicate `foo-1` IDs. Anchor links are appended before `collectTOC`, so enabled anchor labels become part of TOC titles. Track all allocated IDs and derive titles before inserting anchors.
- [ ] **P2 — Complete external/internal link validation.** External link extraction walks only page Markdown `ast.Link` nodes: section links, autolinks, raw HTML, HTML shortcodes and template-generated links escape checking. Internal `@/` resolution checks only the content path, not target anchor existence. Validate links against final HTML/output and honor separate internal/external severity policies.
- [ ] **P2 — Repair MemoryFS contracts.** `normalize` accepts the exact name `..`; `RemoveAll(".")` leaves files intact because none match the `./` prefix. Directory handles lack `fs.ReadDirFile`; file/directory conflicts are allowed; permissions/modification times are discarded. Define the intended `io/fs` compatibility and add table tests for root removal, traversal, directory reads and conflicting paths.
- [ ] **P2 — Implement or remove ineffective options.** `BuildOptions.Concurrency` is passed into `renderAllPages` but ignored in favor of GOMAXPROCS; `ServeOptions.Fast` and `Force` are unused (serve always forces); the README describes `paths_keep_dates` as output mtime preservation while the code uses it to retain filename dates in URL slugs. Align flags/config, behavior and documentation.
- [ ] **P2 — Fix explicit config discovery and validate configuration.** `DiscoverConfigPath` with explicit `--config` stops before checking the filesystem root and mishandles absolute config paths by joining them to each ancestor. `Validate` accepts relative/non-HTTP base URLs, does not validate link-check severity/positive timeouts, and silently ignores unknown config keys. Normalize validated values, retain TOML metadata for unsupported-key diagnostics, and distinguish explicit empty settings from missing settings when merging themes.
- [ ] **P1 — Serve the current preview origin and correct HTTP behavior.** `serve --port`/`--interface` do not update the configured base URL, so generated links can point at production or the old local port. Live-reload URLs use the bind interface, which is unsuitable for remote clients when bound to `0.0.0.0` and improperly formats IPv6. Build preview URLs from an explicit advertised origin; construct WebSocket URLs in the browser from `location`; use `net.JoinHostPort`. Memory lookup of `/post` does not resolve `/post/index.html` and instead falls through to disk; missing pages do not use generated `404.html`, and memory-served images/SVG/fonts get `application/octet-stream`. Use standard HTTP serving primitives/MIME handling and test clean URLs, HEAD, 404 status, IPv6 and subpath hosting.
- [ ] **P2 — Expose usable content metadata in templates.** `pageView` returns `pg.Assets` as absolute source filesystem paths, although README documents asset URLs; `pageNeighbors` always returns nil for `earlier`/`later`; parsed page authors are not exposed. Section front matter has no `extra` field, and section shortcode/TOC/summary metadata is absent. Provide asset URLs, real section-order neighbors and consistent page/section context; add template integration tests.
- [ ] **P2 — Tighten content naming, slugging and front matter checks.** `collectContentFiles` treats every basename beginning `_index` as a section, so `_index_notes.md` is misclassified. `slug.Normalize` drops every non-ASCII letter, making many titles/terms become empty and collide at fallback slugs. Explicit slugs on bundle `index.md` are discarded in `parsePage`; invalid supplied dates are silently ignored. Define multilingual filename/slug policy, detect empty/colliding slugs, and report malformed metadata with source locations. Test accented/non-Latin titles and explicit bundle slugs.
- [ ] **P2 — Escape output according to its context.** The alias template interpolates `url | safe` inside JavaScript, HTML attributes and a meta-refresh value; quotes or `</script>` in a configured URL can break markup/script. `get_url` returns safe strings and several fallback renderers concatenate titles/URLs as HTML. Use JSON encoding for JavaScript strings, HTML escaping for attributes/text, and fail instead of emitting ad hoc fallback HTML.
- [ ] **P2 — Decide how non-rendered content participates in derived outputs.** `search.BuildIndex` indexes `render=false` pages/sections and root `renderFeed` includes all library pages, producing links to outputs that were deliberately omitted. Section aliases are also generated without checking section render status. Define and apply one inclusion policy for listings, links, aliases, feeds and search; avoid indexing nonexistent targets.

## API and improvement candidates

- [ ] **P3 — Offer context-aware link checking with explicit policy.** Accept `context.Context`, a configurable concurrency limit and injected HTTP client; separate external-link severity from `internal_level` (currently `runCheck` uses internal severity for external failures). Return structured diagnostics suitable for CI and editor integrations.
- [ ] **P3 — Expose a supported Go embedding API.** All functionality lives under `internal/`, so external Go programs cannot import the generator. Add a small public package with `Build(ctx, options)` and `Check(ctx, options)`, injected source/output filesystems and immutable effective configuration. Return a `BuildResult` with artifacts, diagnostics, timings and dependencies. Keep CLI/server as adapters; do not make every internal type public.
- [ ] **P3 — Make checks observational.** `kopkop check` currently builds to disk with `Force: true`, deleting the existing output. Render to a temporary or memory target and check that manifest; offer structured JSON diagnostics and explicit refresh/network policy flags for CI.
- [ ] **P3 — Add explicit template/shortcode extension points.** Provide a registry for custom functions, filters, shortcode renderers and post-render transforms, with namespaced names and collision diagnostics. Expose full page/section/config context to shortcodes (currently only a small page map is provided). Track helper file/network dependencies so dev watching and incremental rebuilding remain correct.
- [ ] **P3 — Expand and stabilize the image API.** Support keyword path/width/height arguments, one-dimension aspect-ratio resizing, fit/fill/crop modes, quality/format and structured results `{url, width, height}`. Current resizing always requires both dimensions and stretches images; installed vips/magick binaries silently change the chosen backend and output. Allow explicit backend selection, document GIF/WebP behavior, add context/time/resource limits and cache transforms by source digest/settings.
- [ ] **P2 — Avoid rebuilding the whole template graph for every page.** `baseTemplateContext` calls `serializedPages`, `serializedSections` and `serializedTaxonomies` per rendered page, each rebuilding map/slice views of the whole library; section views call back into `pageView` as well. Work/allocation grow roughly quadratically with page count. Precompute immutable views once after all content is rendered, share them across page contexts, and benchmark real 1k/10k-page builds before choosing broader concurrency changes.
- [ ] **P3 — Implement incremental builds from a dependency graph.** Track templates/includes, ancestor section configuration, content links, shortcode helpers, loaded data and image sources. Invalidate affected outputs and remove deleted outputs; then give `--fast` a measured, documented contract. Surface rebuild failures in the browser while retaining the last good snapshot.
- [ ] **P3 — Declare and test the Zola compatibility scope.** The config/content models do not implement language maps/default languages, localized content graphs, taxonomy pagination settings or a compatible search format. Add an explicit supported/unsupported matrix and a pinned reference Zola version. Prioritize i18n, theme compatibility and search based on target sites; reject unsupported settings instead of silently accepting them. README currently promises Go 1.22+ while `go.mod` requires Go 1.25.6; align installation requirements too.
